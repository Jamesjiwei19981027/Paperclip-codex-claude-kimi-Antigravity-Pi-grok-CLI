# 12. 验收清单

原始定义来自 `doc/plans/2026-10-27-member-agent-phase6-installer-spec.md` 第 8.2 节；命令依据 `doc/plans/2026-10-27-member-agent-phase6-evidence/acceptance.md`。该证据文档明确写过命令未执行、I9 未在第二台真机执行；这些是当时记录，不可抄作本次成功证据。负责人后来提供的中文 Windows 用户名、代理、团队和恢复观察也必须标明版本及验证范围。

在没有仓库、没有预装 Node 的 Windows 电脑，非管理员身份执行。成员负责本机操作，负责人从授权看板读回，二者证据互补。为测试使用专用项目/任务，不覆盖成员真实工作。先核对分发 ZIP 哈希，再解压。下列变量均由环境或交互取得，不粘贴真实路径到报告：

```powershell
$packageDir = Read-Host '解压后的安装包目录'
$programRoot = Join-Path $env:LOCALAPPDATA 'Programs\PaperclipMemberAgent'
$configDir = Join-Path $env:APPDATA 'paperclip-member-agent'
$startFile = Join-Path $programRoot 'start.ps1'
```

每个验收项记录：日期、代理/执行器/Node 版本、系统与 PowerShell 版本、用例编号、操作、脱敏结果、证据文件、结论（通过/失败/未测）。公开材料中的 run/issue 标识使用本次脱敏代号，受控环境保留对应关系。凭据、真实地址、主机名和成员目录不得上传公开仓库。

## I1–I9 原始编号与含义

### I1

原定义：**I1**：解压后 `install.ps1` 全程走完，自检五项通过；

- 怎么做：在解压目录运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1`，按隐藏输入填写成员 Key、配置和工具登录；随后用稳定启动器执行 `-Mode check`。
- 通过：安装无提权、退出成功，五项均通过，版本目录/指针存在，平台连接成功。新执行器若调整检查项目，保留 I1 编号并列清差异，不伪称原五项仍适用。
- 证据：脱敏安装输出、五项自检、版本指针与看板在线截图；不收集登录文件内容。自检成功不等于模型服务联网成功，I3 另验。

### I2

原定义：**I2**：注销后重新登录，代理自动上线（看板显示该智能体连接；由负责人读回）；

- 怎么做：成员保存其他工作后注销并重新登录；查看 `Get-ScheduledTask -TaskName 'PaperclipMemberAgent'` 和近期 launcher 日志；负责人刷新看板。
- 通过：当前用户的受限计划任务自动启动，代理连接 ready，无手动运行脚本；看板确认对应连接，不能只凭“进程存在”。
- 证据：脱敏触发器/运行状态、登录后时间线、看板连接读回。不要导出含真实账户的任务 XML 到公开报告。

### I3

原定义：**I3**：派一个类似 S2 的真实小任务，成功并写回；

- 怎么做：专用测试项目中派任务：读取 README，向专用测试文件追加唯一标记，运行 git --version，评论结果并走真实评审/确认流程。成员只核对本机测试文件；负责人读回运行、评论与评审。
- 通过：CLI 实际改文件、命令成功、平台评论作者正确、评审/确认路径有效，结果/用量出现。仅设置 in_review 或模型文本说成功不算；原 S2 名称在此用具体行为展开。
- 证据：脱敏任务和运行代号、文件差异/哈希、命令输出、评论与评审截图、run 次数和用量。新执行器应同时证明 REST 环境变量确实可用。

### I4

原定义：**I4**：在任务管理器结束代理的 `node.exe`，代理在 30 秒内自动重启并重新连接；

- 怎么做：先在无活动任务时，从 agent-control.json 读身份，并通过进程可执行路径、创建时间确认属于本安装，再结束该 Node。记录旧身份/时间，持续观察新身份和看板连接。
- 通过：30 秒内新进程出现且重新连上平台，未影响其他 Node。I4 的 30 秒必须原样保留；后面的自动恢复扩展有另一个目标，不能相互替代。
- 证据：脱敏前后 PID/创建时间、结束/重连时间戳、launcher 首档 10 秒重试日志、看板读回。

### I5

原定义：**I5**：在整台电脑上搜索 Key 明文，找不到（检查安装目录、配置目录、日志、计划任务定义）；

- 怎么做：由成员在本机隐藏输入待查 Key，只在内存中匹配 UTF-8/UTF-16LE 字节及计划任务定义；只输出命中数量或文件类别，不输出匹配内容。可参考原 evidence 文档的 SecureString/BSTR 清理流程；额外在成员权限范围内检查其他磁盘。
- 通过：规定范围无明文命中，加密 Key 存在且其他 Windows 用户不能解密。若只扫描程序管理目录，就明确“仅该范围未命中”，不能声称已扫描整机。
- 证据：扫描范围、编码、文件数、是否命中、DPAPI 跨用户验证结论；不保存待查 Key、凭据内容或未经脱敏的文件路径。执行器登录凭据可能按工具自身格式存在于专属 home，不得把此项偷换为“工具登录没有文件”。

### I6

原定义：**I6**：制作一个版本号加一的安装包，运行升级：配置、Key、Codex 登录全部保留，看板上显示新版本已连接；再执行回滚，回到旧版本；

- 怎么做：在隔离构建环境制作递增版本包，核对哈希；升级前仅在本机记录配置关键字段、加密 Key/登录文件哈希，升级后比较是否保持。再运行新包 `install.ps1 -Rollback`，检查 current/previous 和程序路径。
- 通过：升级、回滚均立即重连；用户配置和凭据保留，新旧指针正确且不超过两个保留版本。新执行器按其专属登录验证，不可沿用 Codex 文件名猜测。
- 证据：版本切换、数据是否一致、check 结果、连接记录、恢复时间。原定义要求看板显示版本，但阶段 6 evidence 已说明 UI 未直接展示 agentVersion；从受控连接记录确认版本，报告 UI 展示缺口，不把在线标签当版本证明。

### I7

原定义：**I7**：服务器把 `minimumAgentVersion` 设为高于旧版本，旧版本代理拒绝任务且看板上能看到原因（可与 I6 合并）；

- 怎么做：只在专用验收服务器，经授权调高 `server/src/adapters/member-agent/settings.ts` 的 minimumAgentVersion；旧版保持连接后派无破坏性任务。
- 通过：旧版保持连接、未启动 CLI，返回 member_agent_version_outdated，说明当前/要求版本和升级办法；升级到满足版本后能接任务。
- 证据：脱敏要求/实际版本、任务拒绝原因、无文件副作用、升级后成功运行。check 遇单实例锁时以既有连接上的任务结果判定，不把退出 5 当门控结论。

### I8

原定义：**I8**：卸载：计划任务和程序目录被删除；选择"保留"的用户数据确实保留；

- 怎么做：运行安装根 uninstall.ps1；分别对配置/Key、工具登录、日志选择保留。之后查任务、程序根目录与三类数据；测试删除选项时使用专用测试账户/数据并逐项确认。
- 通过：代理离线，计划任务与程序目录删除，选择保留的数据仍在，超过看门狗周期也不复活；选择删除的专用数据确已删除。
- 证据：脱敏选择与存在性结果、任务查询为空、看板离线和等待时间。不要用递归文件列表泄露凭据文件内容或真实路径。

### I9

原定义：**I9**（如条件允许）：在 Windows 用户名或安装路径含中文的电脑上重复 I1。

- 怎么做：在中文 Windows 用户名、PowerShell 5.1、CP936 的非管理员电脑，使用中文/空格解压路径重复 I1，再运行 I3。
- 通过：校验、复制、ACL、登录、自检、CLI 读写和平台写回成功，中文控制台/日志正常；自动化临时中文目录不能替代真实 Windows 用户配置目录。
- 证据：只记录“中文 Windows 用户名”、引擎/代码页/版本、脱敏输出和看板读回。无合适设备时标未测，不填通过。

## 扩展验收：实时过程显示

- 怎么做：运行至少两次可区分的工具调用，中间输出文字，让任务持续到负责人能观察；看板运行详情保持打开。保留脱敏原始 stdout JSONL 与对应帧时间。
- 通过：运行尚未结束时 tool_call、输出、tool_result 和助手文字逐条出现；历史重开仍可解析，JSON 拆包、中文和无末尾换行不丢失。只出现最终结果不算。
- 证据：带时间的脱敏截图或录像、JSONL fixture、frame 与转写对应关系。若 CLI 只在工具完成后给聚合输出，按实际粒度说明，不能承诺逐 token 显示。
- 位置：`ui/src/adapters/member-agent/index.test.ts`、`ui/src/adapters/transcript.ts`、`member-agent/src/job-runner.ts`。

## 扩展验收：一次任务内的团队并行

- 怎么做：一次顶层任务要求 3 个子智能体并行，预先约定各自独占不同测试文件、一个协调者整合；记录各自开始/结束与修改归属。不能用给三个成员代理各派任务来替代此用例。
- 通过：同一次运行内存在真实重叠工作，3 份产物正确且互不覆盖，主智能体整合后实际写回平台；用量与费用证据完整。没有所有派生事件时以输出、时间线和文件结果佐证，不能只用模型自述。
- 证据：脱敏提示、时间线、文件差异与归属、最终整合、token/cache 用量。负责人已测不同文件约 2 分钟重叠；同文件冲突未测，报告此限制。原始 JSONL 只出现 wait 类协作事件并不证明没有子智能体。
- 位置：Codex 的复用适配器与 stdout 贯通路径；`member-agent/test/codex-integration.test.ts` 只证明真实 CLI + 假模型链路，不证明团队模式。

## 扩展验收：自动恢复与重新领取

- 怎么做：分别在空闲和专用可重试任务进行时结束本安装 Node；另一次核实身份后结束启动器。记录进程、断线、旧 run 终态、重新领取和新 run；确保取消/清理后才允许重试，不能同时执行两份任务。
- 通过目标：结束进程后 10 秒～3 分钟内恢复，平台再次领取任务并完成，旧任务无跨新连接日志重放。I4 另外要求 Node 30 秒内，两个结论分别记录。
- 当前限制：Node 首次异常重试为 10 秒；启动器看门狗为 5 分钟，因此不能静态保证启动器每次在 3 分钟内恢复。目标未达就报告失败/差距，经授权另行改进周期；不能篡改原验收阈值。重连也不自动证明旧任务会重领，服务器可能保留失败/error，需验证已有恢复调度或执行一次授权重试。
- 证据：脱敏时间线、前后进程身份、看板新旧运行与领取记录、文件无重复副作用、旧树已结束。正常 0 和终止配置错误应按停止标记保持停止，不能当崩溃重试失败。
- 位置：`member-agent/installer/start.ps1`、`member-agent/installer/install.ps1`、`member-agent/src/connection.ts`、`server/src/services/heartbeat.ts`。

## 扩展验收：同版本覆盖与失败保护

- 怎么做：同版本重新安装，回车沿用配置；检查停止标记清理后立即上线。再用专用损坏测试包触发验证失败，核对旧程序与指针未被破坏；升级/回滚/卸载分别按 I6/I8 执行。
- 通过：重复 ACL 无 SeSecurityPrivilege 错误；配置、Key、登录保持；合法覆盖立即启动；损坏包不替换当前版本。失败/取消维护状态清楚，可修复后重新安装恢复。
- 证据：前后指针/用户数据一致性、退出码、脱敏维护与停止标记状态、立即重连记录。不得只测“新机器首次安装”。
- 位置：`member-agent/test/installer-scripts.test.ts`、`member-agent/test/installer-lan-fixes.test.ts`、`member-agent/test/install-control-integration.test.ts`。

## 13. CLI 实测脚本的记录模板

脚本应在专用试验目录运行，只启动自己创建的进程，收尾核对身份；默认不采集登录交互内容、不打印完整环境。以下是字段模板，不是已经获得的测试结果。每个版本各记一份：

```text
记录编号、日期、试验脚本版本、源码基线、是否有未提交实现变更
系统版本、体系结构、PowerShell 引擎/版本/代码页
中文 Windows 用户名场景：是/否；路径含中文/空格：是/否
CLI 名称/版本、官方来源类别、二进制固定校验位置及核对结论
非交互参数、参数数组、stdin 是否关闭、cwd 类别（不记真实路径）
执行器专属 home 变量、配置位置类别、凭据实际位置类别
登录/任务/续接/注销：专属目录之外写入情况、个人配置是否变化
命令开始/首输出/工具开始/工具结束/末输出/进程退出时间
stdout 格式与事件类型、逐行或聚合、stderr 格式、脱敏 JSONL 文件
meta/event/usage 映射、输入/输出/cache token、计费口径、缺失字段
退出码/信号/超时、错误码、是否错误也返回退出 0
代理选择来源、仅子进程生效结论、平台直连结论（不记真实地址）
取消时刻、AbortSignal、宽限时长、根 PID/创建时间、后代快照
父先进程退出场景、孤儿结果、PID 复用保护、采样器收尾

四个 task markdown 的实际提示包含情况、恢复 REST 写回结果
团队子智能体数、每个文件归属、重叠时间、同文件冲突是否测过
结论：通过/失败/未测；证据文件；限制；下一步
```

记录脚本本身的退出码与收尾结果。实测成功后将可公开的最小 stdout 片段制成 fixture，再测试解析和帧往返；不要把整段个人 CLI 会话、配置或日志直接提交公开仓库。
